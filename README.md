# Сервис автоматического составления расписания

Строит несколько лучших вариантов семестрового расписания колледжа по справочникам, учебной
нагрузке и пожеланиям преподавателей (Google OR-Tools CP-SAT). Готовы все этапы плана — 1–8:
- ядро: доменная модель, синтетика, быстрые проверки, решатель, аудитории, независимый
  валидатор, CLI;
- Django-админка для ввода данных: справочники, нагрузка, блоки, объединения, импорт и экспорт
  xlsx, запуск решателя с сохранением вариантов в БД;
- вход преподавателей по коду на почту и их страница «Мои пожелания»;
- выгрузка расписания в Excel и календари, размещение на сервере (этап 8);
- фоновый расчёт кнопкой «Построить расписание» с прогрессом и остановкой и API `/api/v1/` для
  программ (этап 5);
- интерфейс диспетчера на React `/app/`: перенос пар мышью с мгновенной проверкой, «закрепить и
  пересобрать», сравнение вариантов (этап 6).

Сверх ТЗ: ИИ-агент диспетчера на локальной модели через MCP-сервер (этап 5б, docs/MCP.md).

**Версия:** 0.13.0, сборка 2026-10-16 (номер виден в шапке админки). В 0.13.0 — английский по

## Быстрый старт

Linux / macOS / WSL2:
```bash
bash setup.sh                       # 6 шагов: Python → .venv → зависимости → (dev) → БД и пример данных → проверка
source .venv/bin/activate

# веб-админка (SQLite в data/dev.sqlite3, синтетический семестр уже загружен)
python manage.py createsuperuser    # вход по почте
python manage.py runserver          # http://127.0.0.1:8000/admin/
python manage.py solve_worker       # во втором окне: обработчик кнопки «Построить расписание»
# интерфейс диспетчера http://127.0.0.1:8000/app/ — собрать один раз (Node.js 22.12+):
#   cd frontend && npm ci && npm run build
python manage.py solve_semester 1 --time 120 --variants 3   # или расчёт прямо в окне, без очереди

# или ядро напрямую, без БД
python schedule_cli.py solve data/problem.json -o output/schedule.json --time 120 --variants 3
python schedule_cli.py validate data/problem.json output/schedule_v1.json --issues
```

PostgreSQL, переменные окружения, команды `manage.py` и возможности админки — [docs/WEB.md](docs/WEB.md).
Форматы xlsx — [docs/XLSX_FORMAT.md](docs/XLSX_FORMAT.md) (шаблон нагрузки временный, ждём образец).

Windows — двойной щелчок по `windows_first_run.bat` или см. [README_WINDOWS.md](README_WINDOWS.md).

Разработчику: `bash setup.sh --dev`, затем `pytest` (быстрые тесты ядра и веба, ~2 мин) и
`pytest --slow` (плюс решатель на полной синтетике). Веб-тесты на PostgreSQL:
`DB_ENGINE=postgres DB_HOST=... pytest tests_web`.

## Команды ядра (`schedule_cli.py`)

| Команда | Что делает |
|---|---|
| `generate -o data/problem.json --planted data/planted.json --tightness 0.5` | синтетическая задача масштаба колледжа (25 групп, 45 преподавателей, 25 аудиторий, 2 языковых блока, потоки, подгруппы, онлайн, мигающие пары, объединения, закрепления) + посаженное допустимое расписание |
| `precheck data/problem.json` | мгновенные проверки разрешимости с понятными сообщениями |
| `solve data/problem.json -o out.json --time 120 --variants 3 --min-diff 10 --preset default` | построить варианты; `--reference old.json` — пересборка с минимальными изменениями; пресеты: `default`, `teachers_first`, `students_first`, `lex` |
| `validate data/problem.json out.json --issues --json report.json` | независимая проверка любого расписания (в т.ч. исправленного вручную) и сводка проблем |
| `show data/problem.json out.json ИС-11 --week even` | сетка группы / преподавателя / аудитории на неделю (`*` — мигающая пара) |
| `bench --seeds 3 --tightness 0.3 0.7 1.0 --time 60` | время до первого решения и качество на синтетике |

Коды выхода: 0 — успех; 1 — ошибка ввода/окружения; 2 — расписание не построено; 3 — есть жёсткие нарушения.

## Что на что похоже на синтетике

`bench --seeds 2 --tightness 0.5 1.0 --time 120` в контейнере разработки: 2 ядра, параллельно шли
другие задачи — то есть заметно хуже целевого сервера.

| seed | Теснота | Первое допустимое | Штраф за 120 с | Посаженное случайное | Жёстких нарушений |
|---|---|---|---|---|---|
| 1 | 0.5 | 2,2 с | 5 096 | 28 372 | 0 |
| 1 | 1.0 | 1,9 с | 13 902 | 55 013 | 0 |
| 2 | 0.5 | 2,3 с | 1 000 | 35 130 | 0 |
| 2 | 1.0 | 1,9 с | 13 138 | 27 447 | 0 |

Ориентир ТЗ «первое решение за секунды» выполнен. «Хорошее за 1–5 минут» и «5 вариантов за
10–20 минут» нужно подтвердить `bench` на сервере организации (8 ядер): решатель не доказывает
оптимальность за это время, качество продолжает расти с ростом времени и числа ядер.

├── frontend/                   # интерфейс диспетчера: React + TypeScript (Vite), docs/FRONTEND.md
├── mcp_server/                 # MCP-сервер агента диспетчера (python -m mcp_server), mcp 1.x и 2.x
├── api/                        # API /api/v1/ (django-ninja): routes.py, schemas.py, auth.py (токен или сессия)

│   ├── admin.py                # админка диспетчера: фильтры, массовые операции, импорт/экспорт
