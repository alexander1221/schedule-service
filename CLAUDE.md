# CLAUDE.md — память проекта для Claude Code

Сервис автоматического составления семестрового расписания колледжа (кафедры **Кино** и **ПиУП**,
площадка ВДНХ). Текущая версия — `scheduler/__init__.py` (сейчас **0.10.0**). Исходное ТЗ
на русском: этапы §13 — 1) домен+генератор+валидатор, 2) решатель, 3) варианты/закрепления/
пересборка/диагностика, 4) Django-модели/админка/xlsx, 5) фоновый запуск + API, 6) UI диспетчера
(React+TS, drag&drop), 7) форма преподавателя + вход по почте, 8) экспорт/развёртывание/документы.
**Готовы 1–5, 7, 8 (5: фоновый расчёт 0.8.0, API 0.9.0). Остался 6.** Сверх ТЗ сделан этап 5б — MCP-сервер
для ИИ-агента диспетчера на локальной модели (0.10.0, docs/MCP.md).

Пользователь — заказчик со стороны колледжа (не разработчик-профессионал, но технически грамотный,
Windows + Ryzen 7 7700). Общение, интерфейс, документация, сообщения об ошибках, комментарии в коде —
**по-русски**. Объяснять результат простыми словами, без внутренней кухни.

```bash

source .venv/bin/activate

python -m ruff check . && python -m ruff format --check .
python -m mypy                               # строго только пакет scheduler (так настроено)
python manage.py makemigrations --check --dry-run
python manage.py runserver                   # /admin/ — диспетчер, /login/ — вход по коду, /me/ — преподаватель
python manage.py solve_worker                # обработчик очереди расчётов (кнопка «Построить расписание»)
python manage.py solve_semester <id> --time 300 --variants 3 [--workers 8] [--reference-variant <id>]  # в окне, без очереди
python manage.py draft_from_schedule <текущее.xlsx> -o <папка>   # черновики из файла расписания учебного отдела
```

Перед сдачей любой работы: ruff, mypy, все тесты (+ `--slow`, если трогали решатель/валидатор/генератор),
`makemigrations --check`. Веб-изменения — ещё и на PostgreSQL.

## Инварианты — не ломать

1. **Валидатор независим от решателя.** Решатель после каждого варианта проверяет его валидатором;
   нарушение → AssertionError. Валидатор не импортирует `scheduler.solver`.
2. **Модель ≥ валидатор по каждому мягкому критерию, равенство при доказанном оптимуме**
   (`test_model_objective_matches_validator`, `test_mixed_format_block_counts_formats_like_validator`).
   Если модель занижает — это баг (так был найден баг смешанного блока в 0.4.2). Новые критерии и
   правила — сразу в обоих местах + тест на совпадение.
3. **Свойство «модель принимает любое допустимое расписание»** (property-тест на посаженных решениях
   генератора). Новое жёсткое правило — поддержать в генераторе, иначе синтетика станет неразрешимой.
4. **Подсказки CP-SAT без повторов**: повтор подсказки одной переменной → `MODEL_INVALID`.
5. **Чистый домен**: `scheduler/` не знает про Django. Всё Django — в `timetable/`, `accounts/`, `portal/`.
6. **Вариант читается по своему снимку** (`problem_snapshot` JSONB), а не по текущим справочникам.
7. **Импорт xlsx атомарен**: при любой ошибке в файле ничего не записывается; режим «только проверить».
8. **Один активный расчёт на семестр** — частичное уникальное ограничение в БД, а не проверка в коде.
   Любой запуск (кнопка, `solve_semester`, будущий API) идёт через `services.runs.enqueue`.
9. **Остановка сохраняет найденное**: `SolveParams.stop` → текущий вариант доводится до аудиторий и
   проходит валидатор; новые места решателя, где идёт поиск, — через `_solve(...)`, иначе остановка их не прервёт.

## Правила работы

- **Версии.** Каждое изменение, которое уходит пользователю, — новый номер (semver) в `scheduler/__init__.py`
  и `pyproject.toml` + раздел в `CHANGELOG.md` (Added/Changed/Fixed/«Проверено» — что реально запускали).
  Новые внешние факты (версии пакетов, поведение библиотек) — в блок «Проверенные факты» CHANGELOG с
  указанием, как проверено. Номер версии виден в шапке админки. **Никогда не перепаковывать под старым номером.**
- **Персональные данные.** Файлы пользователя содержат реальные ФИО — их не класть в репозиторий,
  тесты, документацию, примеры. В тестах — только вымышленные имена (пример — `tests_web/test_draft_importer.py`,
  книга воспроизводит структуру на выдуманных данных). `data/`, `output/`, `backups/`, `.env` — в .gitignore.
  152-ФЗ: хостинг и почта — в РФ.
- **Зависимости**: pin в `pyproject.toml` + `requirements.txt` (с комментарием «зачем»), lock-файлы с хэшами:
  ```
  uv pip compile pyproject.toml --generate-hashes --python-version 3.13 --universal -o requirements-lock.txt
  uv pip compile pyproject.toml --group dev --generate-hashes --python-version 3.13 --universal -o requirements-dev-lock.txt
  uv lock
  ```
  Python ≥ 3.12 (требование Django 6.1). Новую зависимость проверять на совместимость с Django 6.1
  (whitenoise 6.12 официально только до 6.0 — поэтому статику раздаёт Caddy).
- **Обёртка проекта** (канон): `setup.sh` без `set -e`, `setup.ps1` и `.bat` — только ASCII (CI проверяет),
  `verify_install.py` — 14 проверок. Архив для пользователя — только через zipfile (совместимость с
  Windows); zip не хранит права на исполнение, поэтому shell-скрипты в доках запускаются как `bash deploy/x.sh`.
- **Миграции** — с осмысленными именами (`00NN_vXYZ_что`); новые поля семестра/элемента — в xlsx-шаблон
  (колонка в конце листа, отсутствующая колонка = значение не трогаем), в `build_problem`, `import_problem`.
- **Веб-интерфейс**: русские подписи, ошибки — что не так и как исправить. Страницы портала: светлая и
  тёмная тема, ширина 390 px без горизонтальной прокрутки страницы (таблицы — внутри `.scroll`).

## Предметные решения (подтверждены заказчиком)

- Двухнедельный цикл, мигающие пары; шкала пожеланий −2…+2 (−2 — жёсткий запрет).
- Кино: дисциплина 1 пара/нед у «единственного» преподавателя → схема **«через неделю»** (ALT_WEEK:
  2 пары подряд в одну неделю, 0 — в другую).
- Английский — **синхронные блоки** с приоритетом; сейчас блоки по сочетаниям групп, как в текущем
  расписании (см. «Открытые вопросы»).
- Потоки кино (2КП1 + 2КП2 одной парой, если совпадают часы и преподаватель); в табель — по каждой группе.
- Элективы/кружки — «ставит диспетчер» (`planning=manual`) + закрепления; киноклуб — Ц1 301, Пт 6–7,
  «можно закончить раньше».
- Дистант ПиУП с бронью аудитории преподавателю (`teacher_in_room`) — тип аудитории не обязателен.
- **Вместимость не учитывается** по умолчанию (`Semester.check_capacity=False`, посещаемость не 100%).
- Аудитория «Ц2 1 этаж новая» — школьная, неактивна.
- Оборудование аудиторий настраиваемо; у преподавателя — необходимое (жёстко) и предпочтительные аудитории (мягко).
- Преподаватель не должен приезжать ради одной пары (мягко, `teacher_min_per_day=2`).
- **ВДНХ (Ц1, Ц2, АРТ) закрывается в 21:00**, 7-я пара 20:00–21:30: на площадке её нельзя, кроме
  `may_end_early`; онлайн из дома — можно.

## Открытые вопросы (ждут заказчика — не решать молча)

1. Английский: обязательно ли подгруппам сочетания заниматься одновременно; блок на весь курс или
   по сочетаниям. В текущем расписании 4 сочетания частично несинхронны (2Ф1+2Ф2, 3Р1+3Ф1, 2ИИ3,
   3 курс кино). Если разносить можно — нужен «частично синхронный блок».
2. 7-я пара онлайн из дома для студентов — оставить разрешённой или сделать нежелательной/запретной.
3. Преподаватели для 3 строк черновика 26/27 и киноклуба — впишет заказчик.
4. Время расчёта на машине заказчика (Ryzen 7 7700, 8 ядер): нужен вывод `solve_semester --time 180 --workers 8`
   на версии ≥ 0.4.2 (прогресс печатается по каждому заметному улучшению).
5. Изменения с даты посреди семестра («с ноября»): действует ли новый вариант с конкретного дня,
   кто утверждает, уведомлять ли затронутых преподавателей.

## Подводные камни (уже наступали)

- OR-Tools `SimpleLinearSumAssignment`: только квадратные задачи; `right_mate()` после неуспеха → segfault.
- `ConstraintProto` не имеет `Clear()` — модель строится заново на каждый вариант/отсечение.
- CP-SAT на тесных задачах: сначала фаза 0 без цели, затем полная подсказка всех переменных.
- Критерии этапа 2 (`ROOM_STAGE_CRITS`: room_changes, room_pref, room_ref) не входят в модель CP-SAT —
  их «модель» это `_cost` в `rooms.py`; новый критерий этапа 2 — в `_cost`, в валидаторе и тест в духе
  `tests/test_room_ref.py`. Жадная склейка мигающих легко ломает такие критерии (так было с room_ref).
- Django 6.1: `EMAIL_*` устарели → `MAILERS`; при заданном `MAILERS` обращение к `settings.EMAIL_BACKEND` падает.
  pytest-django `mailoutbox` с `MAILERS` работает.
- Консольный почтовый бэкенд печатает тело в base64 — поэтому код входа дублируется в лог читаемо.
- gunicorn ≥ 25.1 создаёт управляющий сокет в `$HOME/.gunicorn` → в образе `--no-control-socket`.
- Тестовый клиент Django в ручных скриптах — `Client(HTTP_HOST="localhost")` (ALLOWED_HOSTS).
- Кириллица в путях Windows и BOM: `.env` читается как `utf-8-sig`.
- Прогресс CP-SAT приходит из потоков решателя — там никакого ORM; в БД пишет один поток `_Reporter`
  со своим соединением (закрывает его сам). Тесты с этим потоком — `django_db(transaction=True)`.
- SDK mcp v2: `mcp.server.fastmcp` нарочно падает (ModuleNotFoundError) — класс `MCPServer` в
  `mcp.server.mcpserver`; типы протокола v2 — snake_case (`is_error`, `input_schema`), v1 — camelCase.
  Аннотации собирать `ToolAnnotations.model_validate({camelCase})` — работает в обеих.
- Ctrl+C (SIGINT) во время `solve` перехватывает сам CP-SAT (`catch_sigint_signal`): поиск заканчивается
  как по лимиту времени, KeyboardInterrupt не возникает, следующие solve тоже сразу выходят (проверено
  0.8.0). SIGTERM Python обработает только после выхода из C++ `solve` → `docker stop` посреди расчёта
