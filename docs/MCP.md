# ИИ-агент диспетчера (MCP-сервер)

С версии 0.10.0 диспетчер может давать поручения словами ИИ-агенту на своём компьютере:
«Иванова с ноября не может в пятницу на 4-й паре, хочет в четверг на 6-й — пересобери и скажи,
что поменяется». Агент через MCP-сервер записывает пожелание, запускает пересборку на сервере
колледжа, ждёт результат и пересказывает, какие пары сдвинулись и кого это затронуло.
**Утверждает вариант всегда человек** — в админке. У агента такого инструмента нет.

```
 диспетчер ⇄ агент + локальная модель ⇄ MCP-сервер (python -m mcp_server) ⇄ HTTPS + токен ⇄ сайт колледжа (/api/v1/)
 └──────────────── компьютер диспетчера ─────────────────────────────────┘                    └─ сервер колледжа ─┘
```

**Модель — локальная.** Облачные модели не подходят: в запросах ФИО и пожелания преподавателей,
а это персональные данные (152-ФЗ). Подойдёт любой агент, который умеет подключать MCP-серверы
по stdio и работать с моделью, запущенной на этом же компьютере (через Ollama, LM Studio и т. п.).
Модели нужен «вызов инструментов» (tool calling). Небольшие модели справляются с отдельными
шагами хуже, чем с короткими поручениями, — проверьте выбранную на сценарии из раздела 5.

## 1. Что нужно

- Windows / macOS / Linux, Python 3.12 или новее (3.10+ тоже работает).
- Адрес сайта расписания, доступный с этого компьютера (например, `https://raspisanie.college.ru`).
- Пользователь с ролью «Диспетчер» и **токен API**: админка → «Токены API» → «Добавить», или на
  сервере `docker compose exec web python manage.py create_api_token disp@college.ru --name "агент диспетчера"`.
  Токен показывается один раз. Права у агента — как у этого пользователя. Всё, что агент меняет,
  видно в админке в «Недавних действиях» и в истории объектов с пометкой «через API, токен «…»».

## 2. Установка

Из папки проекта (нужны только `mcp_server/` и файлы `requirements-mcp-*`):

Windows (PowerShell):
```powershell
py -3.13 -m venv .venv-mcp
.venv-mcp\Scripts\python -m pip install --require-hashes -r requirements-mcp-v1-lock.txt
```

Linux / macOS:
```bash
python3 -m venv .venv-mcp
.venv-mcp/bin/python -m pip install --require-hashes -r requirements-mcp-v1-lock.txt
```

## 3. Проверка связи

```powershell
$env:RASPISANIE_URL = "https://raspisanie.college.ru"
$env:RASPISANIE_TOKEN = "rsp_…"
.venv-mcp\Scripts\python -m mcp_server --check
```

Ожидается:
```
Библиотека mcp 1.30.0 (v1) — поддерживается.
Сервис расписания 0.10.0: вход как Диспетчер <disp@college.ru>.
Права: всё нужное есть.
```

## 4. Подключение к агенту

Агент сам запускает сервер командой `python -m mcp_server` из папки проекта. Во многих клиентах
настройка задаётся в формате `mcpServers` (подставьте свои пути):

```json
{
  "mcpServers": {
    "raspisanie": {
      "command": "C:\\raspisanie\\.venv-mcp\\Scripts\\python.exe",
      "args": ["-m", "mcp_server"],
      "cwd": "C:\\raspisanie",
      "env": {
        "RASPISANIE_URL": "https://raspisanie.college.ru",
        "RASPISANIE_TOKEN": "rsp_…"
      }
    }
  }
}
```

Если клиент не поддерживает `cwd`, добавьте в `env` строку `"PYTHONPATH": "C:\\raspisanie"`.
Токен храните только в этой настройке и не пересылайте: с ним можно менять пожелания и запускать расчёты.

## 5. Что умеет агент

| Инструмент | Что делает |
|---|---|
| `semesters` | семестры, утверждённый вариант, идущий расчёт |
| `find_teacher` | найти преподавателя по части фамилии → teacher_id |
| `find_in_variant` | найти группу / преподавателя / аудиторию в варианте → key |
| `schedule` | расписание группы / преподавателя / аудитории на нечётную или чётную неделю |
| `teacher_wishes` | пожелания преподавателя (−2 нельзя … +2 очень удобно) |
| `set_teacher_wish` | записать пожелание на один слот |
| `lessons` | занятия преподавателя или группы (item_id, закрепления) |
| `pin_lesson` / `unpin_lesson` | закрепить занятие в слоте / снять закрепление |
| `check_semester` | быстрая проверка данных перед расчётом |
| `start_rebuild` | пересборка от утверждённого варианта (минимум изменений: время и аудитории) |
| `run_status` / `stop_run` | ход расчёта / остановить с сохранением найденного |
| `variants` | варианты семестра: штраф, сколько сдвинуто, сколько сменили аудиторию |
| `compare_variants` | что изменилось и кого затронуло |
| `check_move` | «что будет, если перенести эту пару вручную» — без изменения варианта |
| `free_rooms` | свободные аудитории на день и пары |

Есть готовый промпт **«Перенос пары по просьбе преподавателя»** (`move_request_prompt`) — пошаговый
план для агента. Пример поручения диспетчера:

> Иванова просит: с ноября не ставить ей пятницу 4-ю пару, удобнее четверг 6-я. Просьба мягкая.
> Пересобери расписание и скажи, что поменяется.

Пересборка по умолчанию идёт 5 минут на вариант. Слишком короткий расчёт (меньше минуты) после
нового запрета может сдвинуть много пар: решатель не успевает вернуться к прежнему расписанию.

## 6. Версии библиотеки mcp: 1.x и 2.x

Код MCP-сервера работает с обеими: всё, чем они различаются, собрано в `mcp_server/compat.py`
(класс сервера `FastMCP` → `MCPServer`, модуль ошибок, имена полей протокола). Проверено на
mcp 1.30.0 и 2.3.0; CI гоняет тесты протокола на обеих, на Linux и Windows.

- Сейчас ставится v1: `requirements-mcp-v1-lock.txt`.
- **Переход на v2** — поставить другой lock-файл, код и настройку агента не трогать:
  ```powershell
  .venv-mcp\Scripts\python -m pip install --require-hashes -r requirements-mcp-v2-lock.txt
  .venv-mcp\Scripts\python -m mcp_server --check     # покажет «mcp 2.3.0 (v2)»
  ```
- Вернуться на v1 — так же, первым lock-файлом.

## 7. Если что-то не так

| Сообщение | Что делать |
|---|---|
| «Токен не принят» | токен отозван, истёк или скопирован не целиком — выпустите новый |
| «Сервис расписания недоступен» | проверьте `RASPISANIE_URL` и что сайт открывается в браузере с этого компьютера |
| «Не хватает прав» (в `--check`) | дайте пользователю роль «Диспетчер» (админка → Пользователи → Группы) |
| «Не установлена библиотека mcp» | раздел 2 — установка в `.venv-mcp` |
| расчёт долго «в очереди» | на сервере не запущен обработчик расчётов: `docker compose ps`, сервис `worker` |
| агент путает дни или придумывает id | модели не хватает «внимательности»: дайте поручение короче или попробуйте модель покрупнее |
