2. Убедиться, что ветка `work` опубликована на GitHub. Отправка из терминала агента
   была заблокирована сетевым доступом; локальное сохранение не означает успешный push.
3. Обновить серверный код до согласованного SHA, сохранив существующий `.env`.
   Учесть remote, указывающий на bundle; не выполнять `pull` вслепую.
4. Если остаётся малый сервер, использовать сборку на ПК и перенос готового образа
   по `deploy/NGINX.md`; сначала подтвердить архитектуру через `uname -m`.
5. До запуска проверить итоговый Compose: публикация только `127.0.0.1:18000`,
   порты 80/443 существующего сайта не перехватываются.
6. Затем выполнить сборку/загрузку образов, инициализацию БД и запуск по руководству,
   проверить HTTPS, статику, вход и расчёт. Реальные данные и регулярные копии —
