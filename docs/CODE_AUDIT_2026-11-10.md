## Основные ошибки

Приоритет P1 — исправить до рабочего запуска; P2 — исправить до соответствующего
сценария использования. «Воспроизведено» означает запуск Python-кода; «по исходникам» —
прослеженный путь выполнения без запуска Django/браузера.

### 1. P1: понижение роли оставляет прежние права

**Место:** `accounts/codes.py:127`, `apply_role`.

При каждом входе роль добавляется через `user.groups.add(group)`. Старые ролевые
группы не удаляются; `is_staff` включается для диспетчера, но не выключается для
преподавателя. Смена роли в белом списке с «Диспетчер» на «Преподаватель» оставляет
доступ к админке и права изменения расписания даже после следующего входа.

**Воспроизведено:** исходная функция извлечена через AST и исполнена с заменителями
объектов Django. После двух вызовов остались обе группы и `is_staff=True`.
Это проверка логики функции, не интеграционный тест авторизации.

**Исправление:** определить порядок отзыва доступа, синхронизировать управляемые
ролевые группы и `is_staff`, сохраняя явно предусмотренные исключения для
суперпользователей. Проверить понижение роли через сессию и API-токен.

### 2. P1: утверждение расписания можно обойти через обычную форму админки

**Место:** `timetable/admin.py:1471`, `ScheduleVariantAdmin`;
`timetable/services/variants.py:123`, `approve_variant`;
`timetable/models.py`, `ScheduleVariant.Meta`.

В форме варианта поле `status` редактируется напрямую. Обычное сохранение статуса
`approved` не вызывает `approve_variant`: обходится независимый валидатор,
а прежний утверждённый вариант не переводится в черновик. Можно получить несколько
утверждённых вариантов одного семестра и неоднозначный выбор расписания в портале.

Дополнительно даже штатный `approve_variant` не блокирует запись семестра и не
защищён уникальным ограничением на утверждённый вариант. Два параллельных утверждения
в PostgreSQL могут оставить два утверждённых варианта, если оба обновления старых
статусов завершатся до сохранения новых.

**Проверено по исходникам.** Нужны интеграционные тесты формы и конкурентного утверждения.

**Исправление:** единый путь утверждения с валидацией, запрет прямого редактирования
статуса, транзакционная блокировка и ограничение БД. При внедрении действия с даты
ограничение нужно проектировать с учётом истории и периодов действия вариантов.

### 3. P1: повторный перенос пары накапливает несовместимые закрепления

**Место:** `frontend/src/App.tsx:187`, `rebuild`;
`api/routes.py`, `pin_create`; `scheduler/solver/cpsat.py`, `_pins`.

Кнопка «Закрепить и пересобрать» только создаёт закрепления. Если сначала перенести
еженедельную пару A → B, а после пересборки B → C, закрепление B остаётся, добавляется C.
Для нагрузки в одну пару в неделю решатель должен поставить её сразу в двух местах:
задача становится неразрешимой. Пользователю придётся удалять старое закрепление в админке.

Также закрепления создаются отдельными запросами до постановки расчёта в очередь.
При ошибке одного запроса или конфликте активного расчёта уже созданные закрепления
остаются, хотя операция в интерфейсе выглядит неуспешной.

**Проверено по исходникам.** Браузерный сценарий не запускался.

**Исправление:** серверная атомарная операция переноса с указанием исходного занятия,
заменой соответствующего закрепления и запуском пересборки. Не удалять остальные
закрепления элемента, если у него несколько пар в неделю.

### 4. P2: календарь не учитывает раннее окончание киноклуба

**Место:** `timetable/export/ics.py:110`, `schedule_ics`.

Валидатор разрешает занятие с `may_end_early`, если оно начинается до закрытия
площадки. Экспорт берёт конец полной пары (`pt.end`), не учитывая закрытие аудитории.
Киноклуб до 21:00 оказывается в календаре до 21:30.

**Воспроизведено:** на маленькой задаче с закрытием аудитории в 21:00 и разрешённым
ранним окончанием валидатор вернул `ok=True`, экспорт —
`DTEND;TZID=Europe/Moscow:20261109T213000`. День выбран для проверки механизма;
ошибка не зависит от дня недели.

**Исправление:** учитывать фактическое раннее окончание события и проверить
одинаковое отображение времени в календаре, сетке и Excel.

### 5. P2: будущий семестр вытесняет текущий в календарной подписке

**Место:** `timetable/services/calendar.py:29`, `current_variant_for_teacher`.

Функция исключает только архивные семестры и сортирует по убыванию `start_date`.
Даты относительно сегодняшнего дня не проверяются. Если заранее утвердить расписание
следующего семестра с нагрузкой преподавателя, подписка уже начнёт отдавать его,
убрав занятия текущего семестра. Возможен и выбор завершившегося неархивного семестра.

**Проверено по исходникам.** Нужны проверки дат и нескольких семестров.

**Исправление:** явно определить покрываемый подпиской период. Либо объединять
события применимых семестров, либо выбирать действительно текущий семестр с учётом
начала, окончания и статуса. Поддержку смены варианта с даты реализовать согласованно.

### 6. P2: роли не получают права на площадки и оборудование

**Место:** `timetable/management/commands/init_roles.py:6`, `TIMETABLE_MODELS`;
`timetable/admin.py:764`, `EquipmentAdmin`; `:777`, `SiteAdmin`.

Список моделей, для которых назначаются права диспетчеру и администратору,
не содержит `site` и `equipment`. Эти модели зарегистрированы в админке, но обычный
пользователь соответствующей роли не сможет управлять ими без дополнительных прав.
Суперпользователь проблему не замечает.

**Проверено по исходникам.** Добавить права и проверить доступ обычных ролевых пользователей.

## Согласованные требования, которые ещё не завершены

Это расхождения с актуальными требованиями, а не доказательство ошибок прежней версии.

| Требование | Что сейчас в коде | Что нужно |
|---|---|---|
| Объединить две группы из трёх; три вместе запрещены | `Merge` и CP-SAT используют набор целиком; `stream_candidates` и действия создания потоков не ограничены двумя группами | Частичный выбор, предел участников и одинаковые проверки во всех путях: решатель, валидатор, формы, импорт |
| Окна преподавателей важнее студенческих | Базовые веса: преподаватели 15, студенты 30 | Пересмотреть веса и пресеты; отдельно согласовать оценку длительного студенческого перерыва |
| Штрафовать окна отдельных подгрупп | Занятость для критерия окон объединяется по группе | Учёт окон подгрупп в решателе и независимом валидаторе без двойного штрафа |

| Лекция допустима в ПК-аудитории | Домен и валидатор требуют точного типа; `alt_room_types` есть в БД, но не используется ядром | Поддержать допустимые типы во всех этапах подбора аудиторий, предварительных проверках и валидаторе |

## Что реально проверено

- Синтаксический разбор **123 Python-файлов** через `ast.parse` — без ошибок.
- **27 существующих тестовых функций** вызваны напрямую, без pytest:
  18 из `tests/test_validator.py`, 4 из `tests/test_compare.py`, 5 из `tests/test_precheck.py`.
  Все прошли. Эти функции не принимают фикстуры; остальные тесты таким способом не запускались.
- Для **10 seed** генератора (6 групп, 12 преподавателей, теснота 0.3): посаженные
  расписания приняты валидатором; сериализация задачи и расписания туда-обратно сохранила данные.
  Это не проверка способности CP-SAT найти решение и не тест производительности на масштабе колледжа.
- Два отдельных воспроизведения: сохранение прав после понижения роли и неверное время
  окончания календарного события при раннем закрытии.

## Ограничения проверки

В окружении Python 3.14.3 и Node 24.14.0; проектный CI проверяет Python 3.12/3.13
и Node 22. Зависимости Python изначально отсутствовали. Создана локальная `.venv`;
установка `pip install --require-hashes -r requirements-dev-lock.txt` завершилась
ошибкой поиска `absl-py==2.5.1`. Это не доказывает ошибку lock-файла: доступность
индекса пакетов в этом окружении не подтверждена.

`npm.cmd ci --offline --ignore-scripts --no-audit --no-fund` не смог завершиться:
в кэше отсутствовал `ws-8.22.0.tgz`. Вызов `npm` через PowerShell также блокируется
политикой выполнения `npm.ps1`; для команд можно использовать `npm.cmd`.

**Не запускались:** полный pytest, CP-SAT, ruff, mypy, проверка миграций,
PostgreSQL, фронтенд-тесты и сборка, браузерные сценарии, MCP-протокол и Docker.
Поэтому утверждать, что приложение целиком запускается и работает, нельзя.
