# API (для программ)

С версии 0.9.0 у сервиса есть API — способ для других программ делать то же, что диспетчер делает
в админке: смотреть расписание, менять пожелания и закрепления, запускать расчёт и сравнивать
варианты. Им будут пользоваться интерфейс диспетчера (этап 6) и ИИ-агент через MCP (этап 5б).

- Адрес: `https://<сайт>/api/v1/`.
- Интерактивная документация со списком всех запросов и кнопкой «Try it out»:
  `https://<сайт>/api/v1/docs` (откроется после входа в админку).
- Ответы — JSON. Ошибки — `{"detail": "что не так"}` по-русски; неверные параметры — код 422
  со списком полей.

## Вход

Нужен пользователь с доступом в админку. Права — те же, что у него в админке (роль «Диспетчер»
может всё). Преподавателям API недоступен.

**Токен** — для программ (MCP-сервер, скрипты). Выпустить:
- в админке: «Токены API» → «Добавить» → после сохранения токен покажется **один раз** вверху
  страницы, скопируйте его;
- или командой: `python manage.py create_api_token disp@college.ru --name "агент диспетчера" [--days 180]`.

Токен передаётся заголовком:

```
Authorization: Bearer rsp_…
```

Отозвать: «Токены API» → выбрать → действие «Отозвать». Хранится только хэш токена: если
он потерян, выпустите новый.

**Сессия админки** — для веб-интерфейса на том же сайте. Изменяющим запросам (POST, PATCH,
DELETE) нужен заголовок `X-CSRFToken` со значением cookie `csrftoken`.

## Запросы

| Запрос | Что делает | Право |
|---|---|---|
| `GET /me` | кто я, версия, мои права | — |
| `GET /semesters` | семестры (`?include_archived=true` — и архивные) | просмотр семестров |
| `GET /semesters/{id}` | семестр: дни, пары, идущий расчёт, утверждённый вариант | просмотр семестров |
| `GET /semesters/{id}/precheck` | быстрая проверка задачи до расчёта | просмотр нагрузки |
| `GET /semesters/{id}/teachers?q=` | преподаватели с нагрузкой в семестре | просмотр преподавателей |
| `GET /semesters/{id}/teachers/{tid}/prefs` | пожелания преподавателя (`"день-пара": −2…+2`) | просмотр доступности |
| `PATCH /semesters/{id}/teachers/{tid}/prefs` | изменить только указанные слоты: `{"set": {"5-4": -2, "4-6": 2}, "reset": ["1-1"]}` | изменение доступности |
| `GET /semesters/{id}/items?teacher_id=&group_id=` | нагрузка с закреплениями | просмотр нагрузки |
| `POST /semesters/{id}/pins` | закрепить пару: `{"item_id": 12, "week": "both", "day": 4, "pair": 6, "room_id": null}` | добавление закреплений |
| `DELETE /pins/{id}` | снять закрепление | удаление закреплений |
| `GET /semesters/{id}/runs` | запуски расчёта, новые сверху | просмотр запусков |
| `POST /semesters/{id}/runs` | построить расписание: `{"time_limit_s": 300, "variants": 3, "reference_variant_id": 7}`; 409 — уже идёт расчёт (`active_run_id`) | добавление запусков |
| `GET /runs/{id}` | ход и итог (`?log=true` — с журналом) | просмотр запусков |
| `POST /runs/{id}/cancel` | остановить (найденное сохранится) или снять с очереди | изменение запусков |
| `GET /semesters/{id}/variants` | варианты семестра | просмотр вариантов |
| `GET /variants/{id}` | вариант: штраф по критериям, число изменений при пересборке | просмотр вариантов |
| `POST /variants/{id}/approve` | утвердить (с жёсткими нарушениями — нельзя) | изменение вариантов |
| `POST /variants/{id}/check` | проверка независимым валидатором; с `{"moves": [...]}` — «что будет, если перенести» (вариант не меняется). У нарушения — где оно: `slot` («день-пара»), `week`, `items` (с 0.12.0) | просмотр вариантов |
| `GET /variants/{id}/entities?by=group\|teacher\|room` | список для сеток | просмотр вариантов |
| `GET /variants/{id}/grid?by=teacher&key=15&week=odd` | расписание группы / преподавателя / аудитории | просмотр вариантов |
| `GET /variants/{id}/free-rooms?day=2&pair_from=3&pair_to=4&week=both` | свободные аудитории | просмотр вариантов |
| `GET /variants/{id}/diff?against=7` | что изменилось: переносы, смены аудиторий, кого затронуло; по умолчанию — против эталона пересборки, иначе против утверждённого | просмотр вариантов |

Дни — 1 (Пн) … 6 (Сб), пары — номера из сетки семестра, недели — `both` (каждую), `odd`, `even`.
В `diff` занятия считаются по неделям цикла: пара «каждую неделю», перенесённая в другой день, —
это 2 переноса (нечётная и чётная).

## Пример: преподаватель просит перенести пару

```bash
T="Authorization: Bearer rsp_…"; A=https://raspisanie.college.ru/api/v1

curl -H "$T" "$A/semesters/1/teachers?q=Иванова"                           # → id = 15
curl -H "$T" -X PATCH "$A/semesters/1/teachers/15/prefs" \
     -H "Content-Type: application/json" -d '{"set": {"5-4": -2, "4-6": 2}}'
curl -H "$T" "$A/semesters/1/precheck"
curl -H "$T" -X POST "$A/semesters/1/runs" -H "Content-Type: application/json" \
     -d '{"time_limit_s": 300, "variants": 2, "reference_variant_id": 7}'      # → run id = 31
curl -H "$T" "$A/runs/31"                                                    # повторять до status = done
curl -H "$T" "$A/variants/42/diff"                                           # что изменилось против варианта 7
```

Утверждает вариант человек — в админке или `POST /variants/{id}/approve`.

**Пересборка.** Решатель старается не двигать пары по времени (`changes` у варианта — сколько
сдвинуто) и с 0.9.1 держит прежние аудитории у занятий, оставшихся в то же время (`room_changes` —
сколько всё же сменили аудиторию: прежняя занята или не подходит).
