# Развёртывание и сопровождение сервиса расписания

Комплект для студентов и сопровождающих. Версия документа 1.1 от 10.11.2026,
для приложения 0.14.0 (ветка `work`). Планируется сервер **185.11.247.226**.
На нём по прежней инструкции был nginx другого проекта: до запуска Caddy необходимо
проверить порты и согласовать совместное размещение. Порядок проверки — в разделе 2.

- [Полная инструкция в Markdown](deployment-guide.md)
- [PDF для чтения и печати](deployment-guide.pdf)
- [Word для передачи и дополнения](deployment-guide.docx)
- [Скрипт резервного копирования](schedule-backup.py)
- [Отдельный тестовый Compose](compose.test.yml) и [Dockerfile проверок](Dockerfile.check)
- [Контрольные суммы](SHA256SUMS.txt)

Сначала прочитайте разделы 1–3. Для действующего сервера не повторяйте установку
с начала: сохраните `.env`, имя Compose-проекта и тома. Руководство покрывает Ubuntu,
Docker Desktop на Windows, PostgreSQL, Caddy/HTTPS, почту, роли, импорт, расчёт,
проверки, резервное копирование, восстановление, обновление и передачу сопровождения.
Известные ограничения версии явно перечислены; успешное развёртывание целиком пока
не подтверждено и должно быть проверено на целевом стенде.

ZIP содержит документацию и вспомогательные файлы, **не исходный код приложения**.
Для использования тестового Compose файлы должны лежать в `docs/deployment/`
внутри репозитория: относительный контекст сборки — два уровня выше. Проверки
запускаются отдельным проектом `schedule-check`, без рабочего `.env` и томов.

`schedule-backup.py` требует Python 3.11+, Docker CLI и доступ к выбранному стеку.
Он создаёт ZIP базы и настроек, но не шифрует его и не удаляет старые копии.
Полученные архивы содержат секреты и персональные данные; их нельзя публиковать.
Пример восстановления останавливает сайт и обработчик, а при ошибке не запускает их.

Проверка логики скрипта без Docker:

```bash
python3 -m unittest discover -s docs/deployment -p test_backup.py -v
```

Эти тесты используют подменённые команды; они не заменяют настоящий pg_dump и
пробное восстановление PostgreSQL. Результаты реальной приёмки заполняются по разделу 22.

## Пересборка документов

Основной источник — `deployment-guide.md`. После правок пересоберите Word/PDF,
контрольные суммы и ZIP командой из корня репозитория:

```bash
python3 docs/deployment/build-kit.py
```

Для сборки нужны Pandoc, XeLaTeX с пакетами `fvextra`/`xurl` и шрифты Arial/Consolas.
Это инструменты выпуска документации, а не зависимости сервиса. Шрифты можно
заменить параметрами `--main-font` и `--mono-font` на установленные с кириллицей.
ZIP по умолчанию создаётся в `output/schedule-service-deployment-kit.zip`.
В Word при необходимости обновите поле оглавления. SHA-256 проверяет целостность,
но не подтверждает доверенность источника архива.
